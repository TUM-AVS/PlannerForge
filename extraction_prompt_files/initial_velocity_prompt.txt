[TASK]
Extract the initial velocity of the ego car from the user's description. Return the result in one of the following JSON formats:

For an exact value:
{
  "initial_velocity": [float]
}

For a range:
{
  "initial_velocity": [float_lower, float_higher]
}

float_lower describes the lower bound (inclusive) of the velocity interval, whereas float_higher specifies the upper bound (inclusive). If the user does not provide a numerical value or range, return an empty JSON object {}.

[CP]
You will either be provided with a range or an exact value. Even though we may have a specific float, it should still be formatted as a list in the JSON object.

In case the user does not provide you with a numerical value or a range of numbers, do not make any assumptions. We only accept numerical values/ranges and not pure verbal descriptions (e.g. "fast", "slow") — for purely verbal inputs without numbers, return an empty JSON object.

Before emitting the JSON, work through the following steps explicitly. Write each step on its own line prefixed with "Reasoning:", then emit the JSON object on a separate line.

1. Scan the input for a numerical velocity. Accept values in m/s, km/h, mph; capture the unit alongside the number.
2. If only a verbal descriptor was given ("fast", "slow", "moderate") and NO number is present, the answer is {} — verbal-only never produces a velocity.
3. Decide if the value is exact, a range, or a lower-bound-only:
   - Exact ("11.99 m/s") → [11.99].
   - Range ("between 5 and 10 m/s") → [5, 10].
   - Lower-bound-only ("at least 5 m/s") → [5, 60] (60 is the safe default upper).
4. If the input uses km/h or mph, convert to m/s (km/h ÷ 3.6, mph ÷ 2.237) — the schema expects m/s.
5. Always wrap the final value(s) in a list, even an exact value.
6. Emit the JSON. {} only when step 2 fires.
