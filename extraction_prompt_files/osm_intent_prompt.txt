{
  "location": {

    "position_keyword": <"start" | "middle" | "end", default "middle">,
    "rectangle_length_m": <number, default 6.0>,
    "rectangle_width_m": <number, default 2.0>
  }
}

Every top-level key MUST be present. Use null (not missing) for nested fields that the user did not specify. Apply the defaults documented in the schema for unspecified fields (density, duration_s, position_keyword, rectangle dimensions). Return ONLY the JSON object, no commentary, no markdown fences.

[CP]
Schema field semantics:

- **location.city**: human-readable city name (e.g. "Munich", "San Francisco"). Leave null only if the user gave explicit bbox coordinates and no city.
- **location.country_code**: ISO 3166-1 alpha-3 (e.g. "DEU", "USA"). Infer from the city if the user did not state a country.
- **location.bbox**: only fill when the user supplied explicit lat/lon corners. Otherwise leave null — the pipeline geocodes from `city`.
- **road_classes**: which OSM road categories to fetch.
    - "roads": main drivable carriageways (motorway, trunk, primary, secondary, tertiary, residential, service, track)
    - "link": ramps and connectors at junctions / interchanges
    - "all": everything
    Default ["roads"]. Include "link" alongside "roads" when the user mentions ramps, slip roads, on/off-ramps, or motorway interchanges.
- **scenario_type**: a hint that helps downstream filtering/ranking; does NOT change which roads are fetched. Pick the single best match. Use "any" only when truly unspecified.
- **sim.duration_s**: extract an explicit simulation duration when the user states one — "simulate 30 seconds" → 30, "for 45 s" → 45, "1-minute run" → 60, "two minutes" → 120 (convert minutes to seconds). If the user gives no duration, default to 20.
- **sim.density**: map an explicit traffic description to a density level — "dense traffic" / "heavy congestion" / "congested" / "gridlock" / "bumper-to-bumper" / "rush hour" / "busy" → "high"; "moderate" / "medium traffic" → "medium"; "sparse" / "light" / "empty" / "quiet" / "calm" → "low". If the user gives no traffic description, default to "low".
- **sim.vehicle_types**: ["car"] unless the user explicitly names other vehicle classes (e.g. "trucks", "ego is the bus") — in that case, include those classes in addition to "car". Never include vehicle classes the user did not mention.
- **ego.strategy** — the ego MUST be a car. The downstream motion planner (Frenetix) is implemented only for cars, so the pipeline filters the dynamic-obstacle list down to vehicles of type "car" before any strategy resolves an ID. Three strategies are allowed:
    - "first" (default): use the first CAR in the simulator's dynamic-obstacle list. Pick this when the user says nothing about which agent is ego, or just says "the ego vehicle" generically.
    - "by_type": **ego.vehicle_type must always be "car"** in our setup. The schema technically accepts other strings but the pipeline will fall back to the first car. The proper handling when the user names a non-car ("ego is the truck", "the bus is the ego", "the third motorcycle"): emit `ego.strategy="first"` instead — i.e. silently downgrade to picking the first car. Do NOT emit `ego.vehicle_type="truck"` etc.; the user's vehicle preference is informational and goes into sim.vehicle_types (so the named class appears as traffic in the scene), but the ego itself remains a car.
    - "by_index": pick the CAR at zero-based index `index`. Use when the user gives a numeric position ("the second car", "the third vehicle"). The index counts cars only — so "the third vehicle" means the third car, not the third dynamic obstacle of any type.
- **goal.strategy**:
    - "trajectory_offset" (default): goal is placed on the ego's own trajectory `offset_steps` simulation steps after start. Use when the user says "drive forward", "continue along the road", or specifies a relative distance ("100 m ahead" — convert to ~10 steps per meter at typical speeds, default 50 if unsure).
    - "specific_lanelet": goal lies on a specific lanelet identified by `lanelet_id`. Only emit this when the user supplied a numeric lanelet ID — never invent one.
- **goal.position_keyword**: where on the goal lanelet the rectangle is centred (start / middle / end). Default "middle". Only meaningful when strategy = "specific_lanelet".
- **goal.rectangle_length_m / rectangle_width_m**: goal rectangle dimensions in metres. Defaults 6.0 × 2.0 (matches the CommonRoad benchmark convention, e.g. AUT_Haag-12_1_T-4).

General rules:
- Apply documented defaults for any field the user did not address.
- Never invent specific numeric IDs (lanelet_id, bbox coordinates) the user did not provide.
- When the user mentions a road code (A8, I-95), fill `location.city` with the road code AND set `scenario_type` to "highway".
- The OSM pipeline can ONLY fetch from real-world locations. Even when the user describes a scenario as "synthetic", "artificial", "handcrafted", or "simulated", you MUST still extract whatever real city or road code appears in the query (e.g. "synthetic network near Vienna" → city="Vienna", country_code="AUT"). Do NOT emit `country_code="ZAM"` — that value is forbidden in this experiment because the pipeline has no real coordinates for it. If the query is fully locationless (no city, no road, no bbox), DEFAULT to `city="Munich"`, `country_code="DEU"`, `bbox=[48.1362, 11.5740, 48.1380, 11.5768]` (a verified-good ~200 m central-Munich neighborhood). NEVER leave all three of city/country_code/bbox null — the pipeline cannot fetch from a null location, so the fallback is mandatory.
