[CP]
Read the .net.xml structure as follows:

- `<edge id="X" function="internal">` blocks describe internal logical edges inside junctions. Users do not route over these — ignore them in your summary.
- `<edge id="X" from="A" to="B" ...>` are the routable edges. Record id, from-junction, to-junction.
- Inside each routable edge, `<lane disallow="...">` lists vehicle classes that may NOT use this edge (e.g. `disallow="pedestrian tram rail_urban"`). If a class is not in `disallow`, it is allowed.
- `<connection from="X" to="Y" ...>` declares a directed connection. Vehicles can travel from X to Y if both edges allow the vehicle's vClass.
- Transitive connections matter: if X → Y and Y → Z exist, the route `X Y Z` is valid.
- `<junction id="J" type="dead_end">` marks J as a network exit — vehicles whose route ends inside the network without reaching a dead-end junction will be flagged as "broken".

Always include in your summary:
1. The set of routable edge IDs.
2. For each edge: from-junction → to-junction, and any non-default `disallow` list. **Be explicit about disallows** — list every restricted vClass for every edge, even if multiple edges share the same set. Downstream routing depends on this.
3. The full list of pairwise connections (both direct and transitive when interesting).
4. Which junctions are dead-ends (exit points).
5. If the user's request mentions a specific edge OR a specific vehicle ID, call out (a) the connections involving that edge, and (b) the disallow set of every edge along plausible routes for that vehicle's vClass. Flag any edge that disallows the user-vehicle's vClass — the downstream router must avoid those.
6. If the user's vehicle has a vClass that is `disallow`-ed by intermediate edges along the shortest path, explicitly call this out and propose an alternative path that respects the disallow constraints. The downstream router cannot infer disallows from the route file alone.
