[TASK]
You will be given a SUMO `.vehicles.rou.xml` route file and a user request to change the driving behavior of one or more vehicles. Pick one of the six named behavior presets, insert it as a new `<vType>`, and reassign the target vehicles to that vType. Emit the **complete updated route file** as your output — only the XML, no commentary, no markdown fences.

The six behavior presets you may choose from are: `balancedType`, `ecoType`, `emergencyType`, `cautiousType`, `aggressiveLaner`, `fastDriver`. Do not invent new presets.

[CP]
Rules when changing a vehicle's behavior:

- The vehicle's `vClass` and `guiShape` MUST be preserved from its original `<vType>`. A bus stays `vClass="bus" guiShape="bus"`; a truck stays `vClass="truck" guiShape="truck"`. If the preset's default `vClass` differs from the vehicle's, create a hybrid vType that carries the preset's behavioral attributes but the vehicle's original `vClass`, `guiShape`, `length`, `width`, `minGap`, and `maxSpeed`.
- Insert the new `<vType>` near the top of `<routes>` with a unique id. Reuse the preset's name (e.g. `balancedType`) or a descriptive variant when carrying preserved vehicle-specific attrs (e.g. `balancedBus`, `fastTruck`).
- Reassign target vehicle(s) to the new vType id. DO NOT change the vehicle's `id`, `depart`, `departPos`, `departSpeed`, or `<route edges>`.
- REMOVE `insertionChecks="none"` from any vehicle whose vType you change — that flag disables safety checks for exact trajectory replay, which is incompatible with dynamic behavior.
- Leave other vehicles and their vTypes byte-equivalent.
- Return the COMPLETE updated route file.

[COT]
Before emitting the updated route file, walk through these reasoning steps explicitly:

  1. (Pick preset) Match the user's behavior word to one of the six presets via the vocabulary table.
  2. (Identify targets) List the vehicle ids the user named. Resolve "all <type>s" by scanning `<vehicle type="X">` where X has the matching `vClass`/`guiShape`.
  3. (Check vClass conflict) For each target, read its current vType. If `vClass`/`guiShape` differ from the preset's defaults (passenger), plan a hybrid vType preserving those fields plus `length`, `width`, `minGap`, `maxSpeed`.
  4. (Inject new vTypes) Add the preset (and any hybrids) as new `<vType>` elements near the top of `<routes>`. Do not delete existing vTypes.
  5. (Reassign targets) Update each target `<vehicle type="...">` to point to the new vType id. Strip `insertionChecks="none"` from each retargeted vehicle. Keep `id`/`depart`/`departPos`/`departSpeed`/`<route>` unchanged.
  6. (Leave others alone) Untouched vehicles and vTypes appear byte-equivalent in your output.
  7. (Emit) Return the COMPLETE updated route file.

End each step on its own line (e.g. `Step 1 (pick preset): "more cautiously" → cautiousType`), then emit the final XML as the last block of output.
